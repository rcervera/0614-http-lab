Nginx no pot processar aquestes dades

Acabes d'enviar el formulari amb el mètode POST: el navegador ha posat el nom, l'email i el missatge dins el cos de la petició HTTP, no a la URL com feia el GET.

Nginx, tal com el fem servir en aquest laboratori, és un servidor estàtic: sap llegir fitxers del disc i enviar-los com a resposta, però no sap interpretar el cos d'una petició ni executar cap tipus de codi. Per això, encara que has fet un POST, Nginx simplement t'ha tornat aquesta pàgina HTML tal qual, ignorant per complet les dades que hi havies escrit.

Per processar de veritat aquestes dades (llegir-les, validar-les, desar-les en una base de dades...) cal un backend: una aplicació que s'executi darrere de Nginx, a la qual Nginx li reenviï la petició (com a proxy invers) o l'hi passi mitjançant FastCGI/WSGI. Alguns dels backends més habituals que es fan servir amb Nginx són:

  • PHP, normalment amb PHP-FPM (FastCGI)
  • Python, amb frameworks com Django, Flask o FastAPI, servits amb Gunicorn, uWSGI o Uvicorn darrere d'un proxy invers
  • Node.js, amb Express o similars, també darrere d'un proxy invers
  • Java, amb Spring Boot o Tomcat, darrere d'un proxy invers
  • Ruby, amb Ruby on Rails (Puma o Passenger)
  • Go, amb el seu propi servidor HTTP darrere d'un proxy invers

Més endavant, en laboratoris posteriors, afegirem un backend real (PHP amb MySQL) per veure com es processen aquestes dades de debò.
